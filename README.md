# Students Database CRUD API

A Python backend for managing student records, built for the **EWB Edu Tech Internship Project**.

- **Core:** Create, Read, Update, Delete students via a REST API (**FastAPI** + **SQLite**)
- **Bonus (optional):** Ask natural-language questions about the data using a local **Ollama** model

> All sample data is **fictional**. Do not commit real student information.

---

## 1. Prerequisites

- Python 3.10 or newer (`python --version`)
- `pip`
- *(Optional bonus only)* [Ollama](https://ollama.com) installed locally

## 2. Installation

```bash
git clone https://github.com/Bitukumar123/student-crud.git
cd student-crud

python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate

pip install -r requirements.txt
```

## 3. Run

```bash
# (optional) load 8 dummy students so you have something to query
python -m app.seed

# start the API
uvicorn app.main:app --reload
```

- API: http://127.0.0.1:8000
- **Interactive docs (Swagger UI): http://127.0.0.1:8000/docs** — you can test every endpoint here by clicking "Try it out".

The SQLite file `students.db` is created automatically in the project folder on first start. Data persists between restarts.

## 4. Student fields

| Field | Required | Notes |
|---|---|---|
| `id` | auto | Unique, generated by the database |
| `name` | yes | 1-100 characters |
| `date_of_birth` | yes | `YYYY-MM-DD`, not in the future |
| `email` | one of email/phone | Valid format, unique (case-insensitive) |
| `phone` | one of email/phone | 8-20 chars: digits, spaces, `-`, `()`, optional `+` |
| `course` | no | |
| `address` | no | |
| `enrollment_date` | no | `YYYY-MM-DD`, not before date of birth |

## 5. API endpoints

| Method | Endpoint | Purpose | Success | Errors |
|---|---|---|---|---|
| POST | `/students` | Create a student | 201 | 422 invalid, 409 duplicate email |
| GET | `/students` | List / filter students | 200 | 422 bad filter |
| GET | `/students/{id}` | View one student | 200 | 404 |
| PUT | `/students/{id}` | Replace full record | 200 | 404, 422, 409 |
| PATCH | `/students/{id}` | Update only some fields | 200 | 404, 422, 409 |
| DELETE | `/students/{id}` | Delete a student | 204 | 404 |

**Filters for `GET /students`:** `name` (partial), `course` (partial), `email` (exact), `born_after`, `born_before` (both strict, `YYYY-MM-DD`), `limit` (default 100), `offset`.

## 6. Testing the API with curl

```bash
# Create
curl -X POST http://127.0.0.1:8000/students \
  -H "Content-Type: application/json" \
  -d '{"name":"Aarav Sharma","date_of_birth":"2004-05-17","email":"aarav@example.com","phone":"+91 98765 43210","course":"Python Backend Development"}'

# List all
curl http://127.0.0.1:8000/students

# Filter
curl "http://127.0.0.1:8000/students?course=python&born_after=2003-12-31"

# View one
curl http://127.0.0.1:8000/students/1

# Partial update (PATCH)
curl -X PATCH http://127.0.0.1:8000/students/1 \
  -H "Content-Type: application/json" -d '{"course":"Data Science"}'

# Delete
curl -X DELETE http://127.0.0.1:8000/students/1

# Missing record -> 404
curl -i http://127.0.0.1:8000/students/9999
```

## 7. Optional bonus: local AI with Ollama

```bash
ollama pull llama3.2:1b      # one-time download
ollama serve                 # skip if Ollama is already running as an app/service
```

Then, with the API running:

```bash
curl -X POST http://127.0.0.1:8000/ai/ask \
  -H "Content-Type: application/json" \
  -d '{"question":"List students born after 2005"}'
```

Example questions: `How many students are there?`, `Which students are in Data Science?`, `What is Aarav's email?`

**How it stays safe and accurate**

1. The model **never writes or runs SQL**.
2. Backend code picks relevant records with fixed rules (year filters such as "born after 2005", course names, student names) using the same parameterised queries as the CRUD API.
3. Those records, plus the total count, are sent to the model as read-only context, and the prompt tells it to use *only* that data.
4. Email/phone are only included in the context if the question asks for them.
5. The response includes `records_used` so you can verify the answer against the data.

"Born after 2005" is interpreted as born in 2006 or later.

Config via environment variables: `OLLAMA_URL` (default `http://localhost:11434`), `OLLAMA_MODEL` (default `llama3.2:1b`), `STUDENTS_DB` (default `./students.db`).

If Ollama isn't running, `/ai/ask` returns a clear `503` message; the CRUD API is unaffected.

## 9. Architecture notes (for your demo)

- **Layers:** routes (`main.py`) handle HTTP and errors; `schemas.py` validates input before it reaches the database; `crud.py` is the only place that talks SQL. This keeps each file small and easy to explain.
- **Create:** `POST` body is validated by `StudentCreate`, inserted with a parameterised `INSERT`, and the stored row is returned with its new `id`.
- **Update:** `PUT` replaces the whole record. `PATCH` loads the existing row, merges in only the fields sent, then **re-validates the merged record**, so you can't, for example, remove both email and phone.
- **Delete:** a single `DELETE ... WHERE id = ?`; if no row was affected the API returns 404.
- **Errors:** missing record -> 404, invalid input -> 422, duplicate email -> 409 (enforced by a `UNIQUE` constraint in SQLite).
- **Security:** every query uses `?` placeholders (no SQL injection); `.gitignore` excludes `*.db` and `.env`.
